# Security & privacy

- Permissions: `storage`, `nativeMessaging`, `scripting`; install-time host access only to youtube.com / music.youtube.com / m.youtube.com. Every other website is an *optional* host permission that the user grants per site from the settings page (Chrome shows its own prompt); a content script is registered only for granted sites and revoking a site removes the permission.
- Website presence reads only the host and first path segment of the page address and maps it to a fixed label (sites.ts). It never reads the DOM, page title, usernames, message text or query strings, never sends a page URL, and is disabled in incognito. A hard-coded blocklist (banking, payments, email, health, government, auth pages, IPs, intranet hosts) applies even to "all other websites". The background validates that web activity comes only from non-YouTube https pages and that YouTube activity comes only from YouTube pages.
- No remote code; CSP `script-src 'self'`. No telemetry; no listening history stored. Media metadata flows only tab → extension → local companion → local Discord.
- Messages: background accepts media only from this extension's content scripts in a tab on an https page (and only the matching kind: YouTube sources from YouTube pages, website activity from other pages), and UI commands only from extension pages. All payloads are re-validated (`normalizeMedia`, `validateHostRequest`): control characters stripped, lengths capped, URLs limited to https + YouTube/ytimg/googleusercontent hosts.
- Native host: manifest `allowed_origins` contains only the extension origin; every message is size-capped (64 KB) and schema-validated; no network listener. Client IDs are public identifiers; there are no secrets in the extension.
- Not used: Discord user tokens, self-bots, token scraping, undocumented endpoints, Discord client modification.
- Local data: settings in `chrome.storage.sync`; "Clear locally stored metadata" empties session/local storage and clears presence.
- Dependencies audited with `pnpm audit` (no known vulnerabilities at time of writing). The companion exe is an unsigned Node SEA binary; Windows SmartScreen may warn. Code-signing is a release TODO.
- Artwork URLs are sent to Discord, whose media proxy fetches them; the image URL reveals which video/track is shown (same as the activity text itself).
